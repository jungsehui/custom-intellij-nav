# Handoff — 2026-10-04 (v3.0.0: the extended toggle goes, the ⌘B migration stays)

Read `2026-10-02-v2.3.5-shipped.md` first.

## What 3.0.0 is

A major release, breaking for exactly one group: anyone whose settings
still say `"customIntellijNav.enableExtendedMacKeymap": true`. That toggle
and the 16 `|| enableExtendedMacKeymap` clauses that kept it working
through 2.x are gone. Those users enable the categories they want instead
(README, *Migrating to 2.0.0 and 3.0.0*).

`enableBundledMacKeymap` and `migrateLegacySettings` were **kept**. That
was the user's choice between two options on 2026-10-04: delete both and
wait for the 2026-10-19 date gate, or keep the migration and need no gate.
Keeping it protects late upgraders however late they are.

## What was measured, not assumed

The first attempt also removed `enableBundledMacKeymap`'s declaration and
ran the existing migration tests as the probe. 12 of 14 failed, in setup:

```
CodeExpectedError: Unable to write to User Settings because
customIntellijNav.enableBundledMacKeymap is not a registered configuration.
```

VS Code will not write, or clear, a key it does not declare, so the
migration's last step would fail on every machine. The declaration went
back, now with "no effect of its own" in its description. No test file was
changed or deleted.

## Added

- `keymap-manifest.test.ts`: every setting a `when` clause names must be
  declared. Mutation-checked: one leftover `|| enableExtendedMacKeymap`
  made it fail, naming exactly that key.
- `enableRefactoringKeymap`'s description no longer says Extract is
  controlled by the extended toggle (stale since 2.0.0).
