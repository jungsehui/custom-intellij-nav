# Handoff — 2026-10-02 (v2.3.5: ⌘W and ⌘\ handed back to VS Code)

Read `2026-10-02-codex-pointers-1140-remeasure.md` and
`2026-10-02-v2.3.4-shipped.md` first; this file records what came after.

## What 2.3.5 is

A patch. `⌘W` → `closeActiveEditor` and `⌘\` → `splitEditor` re-bound
chords to the commands VS Code already gives them, with no focus
condition. The only effect was priority (400 against 200), which took
contextual defaults away: Close Window, Close Group, Restore Auxiliary Bar
and Kill Terminal Editor for `⌘W`; Split Terminal and Split Active Tab for
`⌘\`. Both bindings are gone, guarded by `src/test/keymap-manifest.test.ts`.
README *Displaced defaults* is now complete for the 25 exposed bindings.

## How it was measured

VS Code was asked for its own defaults: a test host with a throwaway
extension reads `vscode://defaultsettings/keybindings.json` (1,306
entries on 1.140.0, macOS). Method, controls and the socket-path trap are
in conventions.md, *Audit the exposed bindings against VS Code's own
default keybindings*. The scratch runner is not in the repo.

## Corrected along the way

- **"14 relied-upon defaults we do not bind" was wrong.** We bind 11 of
  them, mostly paired with a camelHumps variant. Only `⌘,`, `⌘↑`, `⌘↓`
  are left to VS Code. The earlier handoff and the vault said 14; this
  file and conventions.md are now correct.
- CLAUDE.md said no binding carries `key`. One does: the Explorer tree's
  `right`. It has done so since before this session.

## Process note
