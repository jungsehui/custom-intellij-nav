## The coverage metric was wrong

Coverage compares unique Mac chords, ours against k--kato's. The
comparison was on raw strings, so `cmd+shift+c` and `shift+cmd+c` counted
as two different chords. VS Code parses them as one.

Recomputed from the tags with modifier order normalized
(`ctrl, shift, alt, cmd`):

| Version | Ours | Overlap | Coverage | Previously published |
|---|---|---|---|---|
| v1.1.0 | 102 | 87 | 55.4% | 53.8% |
| v1.2.0 | 121 | 106 | 67.5% | 65.8% |
| v1.3.0 | 125 | 109 | 69.4% | 67.7% |
| v1.4.0 | 131 | 115 | 73.2% | 71.5% |
| **v1.5.0** | **141** | **125** | **79.6%** | — |

k--kato's denominator is 157, not 158 — it too had one chord counted
twice. v1.0.1 has no tag, so its 37.6% stands as recorded.

## Two measurement traps this milestone

**Loop-registered keybindings are invisible to a literal grep.** `⌘7`
measured as free. That is also exactly what `⌘1`–`⌘9` looks like when
registered as `KeyCode.Digit1 + index` — no `Digit7` literal exists.
Searching the `Digit1 +` / `Digit0 +` forms found only the Sessions window
and a `⌘K ⌘0` chord, so the answer held. It would not always. Same shape
as `terminalFocus` being declared through an enum constant in v1.4.0.

**A key can be a chord prefix.** `⌘;` showed hits in the testing
commands, but every one was `KeyChord(⌘;, …)` — `⌘; A` runs all tests,
with five more hanging off the same prefix. Binding `⌘;` alone does not
displace one command, it kills the family. Grep for `KeyChord(` before
judging a key cheap.

## Shipped (11)

- **Tool Windows** — `⌘7` Structure, `⌘⇧'` Maximize, `⇧⎋` Hide active
  tool window (three entries: sidebar / secondary sidebar / panel)
- **VCS** — `⌃⌥⇧↓` / `⌃⌥⇧↑` next / previous change
- **Diff** (new toggle) — `F7` / `⇧F7` next / previous difference,
  `⌃⇧⇥` focus other side. All gated on `textCompareEditorVisible` or
  `activeCompareEditorCanSwap`, so inert outside a diff editor.
- **Workbench** (new toggle) — `⌘⇧C` Copy Path, `⇧F12` Restore Default
  Layout, `⌃⌘F` Toggle Full Screen (already the default, registered
  explicitly)
