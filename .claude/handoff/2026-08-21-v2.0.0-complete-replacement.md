## The structural change

Until now the keymap had two axes that disagreed. `⌘⌥V` Extract Variable
lived under `enableExtendedMacKeymap`; `⇧F6` Rename lived under
`enableRefactoringKeymap`. Same kind of thing, different toggle.

2.0.0 collapses it to one axis plus one deliberate exception:

- **11 functional categories**, all default off. Each displaces VS Code
  defaults, so opt-in per area.
- **One feature toggle**, `enableGoToDeclarationOrUsages`, default **on**.
  `⌘B` is not a keymap remap — it is the extension's own command and the
  reason most people install this.

Backward compatibility is exact, not approximate:

- `⌘B` fires on `enableGoToDeclarationOrUsages && enableBundledMacKeymap`.
  Both default true → unchanged. Explicitly set the old one to false →
  still off. Set the new one to false → off.
- The 15 moved bindings fire on `(newCategory || enableExtendedMacKeymap)`.
  An existing `enableExtendedMacKeymap: true` keeps all 15 alive.

Both deprecated settings carry `deprecationMessage`, so VS Code
strikethroughs them in the settings UI. **Remove them in 3.0.0** — that is
the one piece of follow-up this design owes.

## Four displacements had been undocumented since v1.0.0

Sweeping all 154 chords against the full VS Code source found:

| Key | VS Code default | Source |
|---|---|---|
| `⌘B` | **Toggle Primary Side Bar** | `layoutActions.ts` L306 |
| `⌘1` | Focus First Editor Group | `editorActions.ts` L303 |
| `⌘0` | Focus into Primary Side Bar | `sidebarActions.ts` L46 |
| `⌘9` | `lastEditorInGroup` secondary (primary `⌥0`/`⌃0` unaffected) | `editorActions.ts` L1446 |

All four are now in the README.

**The sweep is a candidate list, not a verdict.** It reported 104 of 154
chords as "overlapping", but most of those hits are narrowly scoped —
chat, terminal, browser view, sessions — and are not displacements.
Telling the two apart mechanically needs every VS Code registration's
`when` parsed, which was not done. The four above were confirmed by
reading them individually. Do not publish the 104 figure.

## Measurement notes worth keeping

- **A platform ternary can free a key.** `⌘⌥N` looked taken by New
  Untitled File, but the expression is `isWeb ? (… ⌘⌥N) : ⌘N` — the
  `⌘⌥N` arm exists only in the web build. Read the expression, not the
  grep line.
- **`⌘1` is not a family.** It is a single explicit binding
  (`focusFirstEditorGroup`); `FocusLastGroupAction` has no keybinding at
  all. So there is no `⌘1`–`⌘9` loop, which confirms the v1.5.0 finding
  that `⌘7` is free.
- **Numpad tokens** come from the KeyCode table's UI label, lowercased:
  `'NumPad_Divide'` → `numpad_divide`, `'NumPad0'` → `numpad0`.

## Numpad mirrors

13 chords, 14 entries, each a **clone** of its non-numpad counterpart —
same command, same `when`. Cloning rather than hand-writing means the pair
cannot drift. `⌘numpad,` was skipped for the same reason `⌘,` was: it is
already `openGlobalSettings`.

## The remaining 19, and why

Eleven are impossible: macOS app switcher (2), double-tapped modifiers
(2), refactor kinds TypeScript does not emit (3), a chord prefix (1),
already-the-default (2), notebook-only (1).

Eight are deliberate refusals: `⌘S` Save All would run `formatOnSave` on
every open file; `` ⌃` `` is Toggle Terminal; `⌃⇥` is already the
switcher; `⌘↑`/`⌘↓` are the macOS document-start/end gesture on keyboards
with no Home/End key; `↩`/`⇥`/`⌃↩` match VS Code defaults already;
`⌘⇧↩` Complete Current Statement is deferred.

Full table with sources is in the README under *Coverage and what is
deliberately missing*.
