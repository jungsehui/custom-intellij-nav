# Handoff — 2026-10-22 (v3.0.1: TypeScript Go named, and a probe to keep it true)

Read `2026-10-22-ci-deps-tsgo.md` first; it found the problem this release
answers.

## What 3.0.1 is

A patch. With `js/ts.experimental.useTsgo` on and a TypeScript Go
extension installed, VS Code hands TS/JS to TypeScript Go, which offers no
refactorings (measured in all four languages it serves). The refactor keys
used to end in a vague "the language server does not implement it, or the
caret is not on something it applies to". Now the status bar reads "No
Extract Variable: TypeScript Go has no refactorings yet" and the
notification names the setting. With the setting on but no TypeScript Go
extension, VS Code keeps its built-in TypeScript, and nothing changes.

## Where it lives

| Piece | File |
|---|---|
| What TypeScript Go lacks (measured table) | `src/refactor/policy.ts`, `isMissingInTypeScriptGo` |
| When TypeScript Go is in charge (VS Code 1.143's rule, read from its bundled code) | `src/core/config.ts`, `isTypeScriptGoServing` |
| The message | `describeOutcome` in `policy.ts` |
| Re-measuring all of it against a real VS Code | `npm run probe:tsgo` |
