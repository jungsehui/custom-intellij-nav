## The two things worth carrying forward

### 1. Enumerate the language server before planning keys

The blocking question was never key conflicts. It was whether the
refactorings exist at all. They are enumerable:

`microsoft/TypeScript@v5.9.2 src/services/refactors/` is 16 files, each
registering a literal `kind:` string. VS Code passes those through
verbatim (`typescript-language-features/.../refactor.ts` `getKind()`), so
that directory **is** the list of what TypeScript can do.

It contains no `refactor.extract.field`, no `refactor.change.signature`,
no `refactor.introduce.parameter`. Three planned keys — `⌘⌥F`, `⌘F6`,
`⌘⌥P` — were dropped for that reason alone. k--kato binds all three; they
are dead keys there.

`⌘⌥F` was doubly wrong: it is the macOS **Replace** shortcut
(`findController.ts` L1011).

### 2. Two of our own keys were already broken

- **`F6` was bound to a command that does not exist.** There is no
  `workbench.action.files.move` in VS Code; the workbench's only file-move
  command is `moveFileToTrash` (Delete). So since v1.0.0 the key did
  nothing *and* displaced `workbench.action.focusNextPart`. Nothing warns
  about this — VS Code accepts a keybinding pointing at any string.
- **`⌘⌥N` (Inline) could silently perform an unrelated refactoring.** Kind
  matching is prefix-based, so the chain's `refactor.rewrite` fallback
  matched `refactor.rewrite.arrow.braces`; being the only match,
  `apply: "ifSingle"` applied it without asking. Pressing Inline rewrote
  an arrow function.

Both are now rules in `.claude/conventions.md`.

## Marketplace publish — resolved

The PAT route was abandoned: creating an Azure DevOps organization kept
demanding a payment card. It is not needed. The official docs describe
manual upload directly:

> "Manually, using `vsce package` to package the extension into the
> installable VSIX format and then uploading it to the Visual Studio
> Marketplace publisher management page"

— https://code.visualstudio.com/api/working-with-extensions/publishing-extension

So: go to https://marketplace.visualstudio.com/manage/publishers/jungsehui,
sign in with the Microsoft account that owns the `jungsehui` publisher, and
upload `custom-intellij-nav-1.3.0.vsix`. No PAT, no organization.

Unverified detail: whether updating an existing extension uses the row's
`⋮` menu or the "＋ New extension" dropdown. The docs show the add flow
only. Check both in the UI.
