## The critical finding

`runRefactor` prefetched against a captured `editor.document.uri` and
`editor.selection`, then dispatched `editor.action.codeAction` — which
takes **no URI and no range** and acts on whatever is focused wherever the
caret is *when it runs*. The provider round-trip between the two is an
await boundary, tens of milliseconds warm and seconds on a cold TS server,
and there was no staleness guard at all.

Failure: caret on `foo + bar` in `a.ts`, press `⌘⌥M`. Prefetch reports one
`refactor.extract.function`. Before it resolves, click into `b.ts`. The
dispatch runs at the new position and, if exactly one action of that kind
matches there, `apply: "ifSingle"` applies it **without asking**.

Same class as the v1.3.0 Inline bug. That fix narrowed *which kind* is
dispatched and left *where* unguarded.

Fixed by extracting `editorMatches` and `selectionMatches` into
`core/snapshot.ts` as pure predicates — they take the editor rather than
reading `vscode.window.activeTextEditor` — and bailing immediately before
dispatch. `navigation/` had a staleness discipline since v1.0.0;
`refactor/` never did. Now both use the same module.

## The three Important findings

1. **A superseded `⌘B` wrote over the one that replaced it.** `peekUsages`
   returned `false` for both "request superseded" and "zero references", so
   the three call sites could not tell them apart. Press `⌘B` twice quickly
   and request 1 could put "No usages found" on the status bar while request
   2 was navigating successfully. Now returns `"shown" | "none" | "stale"`.
   The `catch` block leaked the same way and now re-checks staleness.
2. **Exceptions were reported as "this language does not support it."** All
   attempts throwing fell through to the not-implemented notification — the
   one message a user acts on, since they would conclude the feature does
   not exist and stop pressing the key.
3. **`enableBundledMacKeymap: false` could not be migrated.** 2.0.0 gated
   `⌘B` on `(new && deprecated)`. Behavior was preserved in all four
   combinations, but a user who followed the deprecation notice and set the
   *new* setting to `true` got nothing — the struck-through setting vetoed
   its own replacement. A `when` clause cannot distinguish an explicit
   `false` from an unset default, so `core/migrate-settings.ts` moves the
   value once at activation. The 17 `||` shims are untouched: those are
   additive and were already correct.

## What was refuted

The reviewer suspected `vscode.executeCodeActionProvider` returns
`disabled` code actions, which would let the prefetch gate pass on an
unusable action and let VS Code raise a toast the extension cannot
suppress. They flagged it honestly as unverified — no VS Code checkout on
their machine.

It returns `codeActionSet.validActions.map(item => item.action)`
(`codeAction.ts` L377), not `allActions`. The concern does not apply.

Worth keeping the shape of that exchange: a specific, well-argued finding
that turned out to be wrong, marked as unverified by the person raising it,
and settled by opening the source. That is the process working.

## The test suite had never run

`npm test` failed with `spawn …/Contents/MacOS/Electron ENOENT`.
`@vscode/test-electron@2.5.2` looks for an executable named `Electron`;
VS Code 1.134's macOS bundle names it `Code`. Upgraded to 3.1.0 and
`@vscode/test-cli` to 0.0.15.

With the harness working, the single pre-existing test turned out to be
wrong: it asserted `intellij.goToDeclarationOrUsages` was in
`getCommands()`, but the extension declares no `activationEvents` and so
activates lazily. Nothing in a test run triggers that, and a
contributed-but-inactive command is not in the command registry. It now
activates in `suiteSetup` and checks both directions — every expected
command registered, and every command the manifest contributes registered.

27 tests now, covering the pure predicates behind the critical fix
(including the moved-caret case against real editors), `location-utils`
dedupe and normalization, the action-table invariants, and the
unsupported-claim policy added afterward.

## Two of my own measurement errors, recorded

1. **The `key`+`mac` count.** I reported "mac 전용 135" by counting entries
   *having* `mac`. The reviewer was right: 128 carried both, 101 with
   divergent chords that could never fire on any platform. All removed.
2. **I read a test exit code through a pipe.** `npm test | tail` reports
   `tail`'s status, so I announced a passing run that had actually failed
   with `Exit code: -2`. I had written the rule "read the exit code
   immediately after the command" into `conventions.md` earlier the same
   session. Read `$?` directly.
